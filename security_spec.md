# Relatório e Especificação de Segurança (Security Spec & Threat Model) — BolaComVisão

## 1. Visão Geral & Invariantes de Dados (Data Invariants)

O BolaComVisão é uma plataforma profissional de gestão técnica para clubes de futebol. A sua arquitetura de segurança segue o princípio de **Zero-Trust (Confiança Zero)**, controlo de acesso baseado em atributos/funções (**RBAC/ABAC**), isolamento multi-clube/multi-escalão e proteção rigorosa de dados pessoais (**PII**).

### Invariantes Fundamentais:

1. **Bloqueio Padrão (Default-Deny)**: Acesso não autenticado é estritamente bloqueado em todas as coleções do sistema (`allow read, write: if false;`).
2. **Administrador Mestre Soberano**: Apenas o email de administração mestre (`375.santos@gmail.com`) ou credenciais aprovadas na coleção `/admins/{adminId}` possuem privilégios para aprovar, suspender, alterar funções ou eliminar utilizadores.
3. **Prevenção de Auto-Elevação de Privilégios (Anti-Privilege Escalation)**: Nenhum utilizador registado pode atribuir a si próprio `role = 'Administrador'` ou `status = 'approved'`.
4. **Isolamento de Utilizadores Pendentes (Pending User Isolation)**: Contas com estado `'pending'` só têm permissão para ler o seu próprio documento `/users/{uid}`. Têm zero acesso à base de dados do clube (`/club_workspace`).
5. **Auditoria Imutável (Immutable Audit Logs)**: Os registos da coleção `/audit_logs/{logId}` apenas permitem escrita do tipo `create` com ID validado e proíbem terminantemente atualizações (`update`) ou eliminações (`delete`).
6. **Integridade de Chaves e Tamanhos (Anti-Denial of Wallet)**: Todos os identificadores, campos de texto e listas têm validação estrita de tipos e limites máximos de tamanho (`.size() <= MAX`).
7. **Isolamento Multi-Tenant**: Dados táticos e desportivos de um clube não podem ser consultados nem modificados por utilizadores de outro clube.

## 2. A Matriz dos Vetores de Ataque ("Dirty Dozen" & Threat Vectors)

| ID      | Vetor de Ataque / Payload Malicioso                                           | Ação / Tentativa de Exploração                                                                                                          | Resultado Esperado     | Mecanismo de Defesa nas Regras                                                                                                                                                                                           |
| ------- | ----------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------- | ---------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **D01** | **Leitura Anónima de Dados do Clube**                                         | `GET /club_workspace/main` sem token de autenticação (`auth = null`)                                                                    | ❌ `PERMISSION_DENIED` | `isAuthenticated() && isApprovedUser()`                                                                                                                                                                                  |
| **D02** | **Despejo / Listagem de Utilizadores Anónima**                                | `LIST /users` sem autenticação                                                                                                          | ❌ `PERMISSION_DENIED` | `isAuthenticated() && (isMasterAdmin() \|\| isApprovedUser())`                                                                                                                                                           |
| **D03** | **Auto-Promoção para Administrador no Registo**                               | `CREATE /users/{uid}` com payload `{ account: { role: "Administrador", status: "approved" } }`                                          | ❌ `PERMISSION_DENIED` | `isMasterAdmin() \|\| (isOwner(userId) && incoming().account.status == 'pending' && incoming().account.role != 'Administrador')`                                                                                         |
| **D04** | **Infiltração de Utilizador Pendente**                                        | `GET /club_workspace/main` com conta autenticada mas `status: 'pending'`                                                                | ❌ `PERMISSION_DENIED` | `isApprovedUser()` verifica rigorosamente se o documento do utilizador tem `status == 'approved'`                                                                                                                        |
| **D05** | **Alteração Arbitrária de Conta Alheia (IDOR)**                               | Treinador A tenta `UPDATE /users/{treinadorB_uid}` para mudar cargo ou estatuto                                                         | ❌ `PERMISSION_DENIED` | Apenas o Master Admin pode alterar contas alheias; utilizadores aprovados só alteram o seu próprio perfil sem alterar role/status                                                                                        |
| **D06** | **Injeção de ID Gigante / ID Poisoning**                                      | Pedido com ID de 500KB de carateres de controlo em `/users/{junkId}`                                                                    | ❌ `PERMISSION_DENIED` | `isValidId(id)` impõe tamanho `<= 128` e padrão regex `^[a-zA-Z0-9_\-]+$`                                                                                                                                                |
| **D07** | **Injeção de Campos Fantasma / Shadow Fields**                                | Escrita em `/club_workspace/main` contendo propriedades não autorizadas ou tipos inválidos                                              | ❌ `PERMISSION_DENIED` | `isValidClubWorkspace(incoming())` valida estrutura obrigatória e tipos                                                                                                                                                  |
| **D08** | **Tentativa de Eliminação de Auditoria**                                      | Treinador tenta `DELETE /audit_logs/{logId}` para ocultar alterações                                                                    | ❌ `PERMISSION_DENIED` | `allow update, delete: if false;` na coleção `/audit_logs/{logId}`                                                                                                                                                       |
| **D09** | **Eliminação Não Autorizada de Contas**                                       | Treinador tenta `DELETE /users/{outroTreinador}`                                                                                        | ❌ `PERMISSION_DENIED` | `allow delete: if isMasterAdmin()`                                                                                                                                                                                       |
| **D10** | **Criação de Documento de Administrador Falso**                               | Utilizador não autorizado tenta `CREATE /admins/{meuUid}`                                                                               | ❌ `PERMISSION_DENIED` | `/admins/{adminId}` permite escrita exclusivamente se `isMasterAdmin()`                                                                                                                                                  |
| **D11** | **Elevação de Privilégios via Update de Perfil**                              | Treinador aprovado tenta `UPDATE /users/{proprioUid}` alterando `role: 'Administrador'`                                                 | ❌ `PERMISSION_DENIED` | `incoming().account.role == existing().account.role` garante imutabilidade da função pelo próprio utilizador                                                                                                             |
| **D12** | **Acesso Direto a Coleções Arbitrárias**                                      | Chamada direta da API a coleção não mapeada `/{colecaoAleatoria}/{docId}`                                                               | ❌ `PERMISSION_DENIED` | Regra raiz de bloqueio universal: `match /{document=**} { allow read, write: if false; }`                                                                                                                                |
| **D13** | **Payload de Estado Gigante / Tipos Errados (Denial-of-Wallet & Corruption)** | Escrita em `/club_workspace/main` com milhares de registos forjados, campos numéricos em vez de listas ou `updatedAt` corrompido/futuro | ❌ `PERMISSION_DENIED` | `isValidClubWorkspace(data)` impõe limites estritos de chaves (`data.size() <= 20`, `state.size() <= 50`), valida tipos de coleções de topo e limita listas (`roster <= 250`, `matches <= 350`, etc.) e timestamp válido |
| **D14** | **Leitura/Escrita em Base de Dados de Outra Equipa (IDOR Multi-Tenant)**      | Treinador da Equipa A tenta `GET` ou `WRITE` em `/team_databases/equipa_B/...`                                                          | ❌ `PERMISSION_DENIED` | `isTeamMember(teamId)` valida rigorosamente que o utilizador tem `teamId` atribuído no seu perfil aprovado (`assignedTeams`)                             |
| **D15** | **Escrita Não Autorizada por Perfil Só de Leitura na BD da Equipa**           | Membro de staff (ex: Analista / Fisioterapeuta) tenta `WRITE` em `/team_databases/{teamId}/datasets/...`                                 | ❌ `PERMISSION_DENIED` | `canEditTeamDatabase(teamId)` restringe permissões de modificação e importação exclusivamente a Administrador, Treinador Principal e Treinador Adjunto    |
| **D16** | **Eliminação de Dataset Inteiro por Não-Administrador**                       | Treinador Principal tenta `DELETE /team_databases/{teamId}/datasets/{datasetId}`                                                       | ❌ `PERMISSION_DENIED` | `allow delete: if isMasterAdmin()` na subcoleção `/datasets/{datasetId}` restringe eliminação de dataset a Administradores                              |
| **D17** | **Injeção de Schema Excessivo / Bloat de Colunas ou Linhas na BD de Equipa**  | Tentativa de gravar dataset com mais de 40 colunas ou rowCount > 5000                                                                   | ❌ `PERMISSION_DENIED` | `isValidTeamDataset(data)` impõe `data.columns.size() <= 40`, `data.rowCount <= 5000`, e `isValidTeamDbRow` restringe mapa a `<= 40` chaves             |
